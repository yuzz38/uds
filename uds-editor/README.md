# ГрафУДС — редактор графа улично-дорожной сети

Веб-редактор улично-дорожной сети в формате OSM. Открывает `.osm`, показывает дороги на карте
поверх подложки (по умолчанию спутник Яндекса; ещё схема Яндекса, Google, 2ГИС, Esri, OSM), даёт править граф мышью и сохраняет результат обратно
в `.osm` — тот формат, который на сервере проверки читают MatSim, SUMO и Webots.

Всё, что не правили, сохраняется как было: теги, отношения (маршруты транспорта), здания,
атрибуты `version`/`timestamp`, порядок элементов.

## Запуск

Нужен любой современный браузер. Выберите удобный способ:

| Способ | Команда | Что нужно |
|---|---|---|
| Двойной клик | открыть `index.html` | ничего; кнопка «Пример» в этом режиме не работает — файл открывается кнопкой «Открыть» |
| Windows | `run.bat` | Python 3 |
| Linux / macOS | `./run.sh` | Python 3 |
| Docker | `docker build -t uds-editor . && docker run --rm -p 8090:80 uds-editor` | Docker; другой сервер проверки: `-e CHECKER_URL=http://адрес:порт` |

**Сайт на GitHub Pages.** Редактор — статический сайт, его можно опубликовать прямо из репозитория:
Settings → Pages → Deploy from a branch → `main` / `/ (root)`. Ссылка
`https://<ник>.github.io/<репозиторий>/?file=example.osm` открывает редактор сразу с картой;
кнопка **QR** показывает QR-код этой ссылки — чтобы открыли с телефона. На Pages нет прокси к серверу
проверки, поэтому отправка из редактора там работает, только если сервер разрешает запросы из браузера (CORS).

Во всех способах, кроме первого и Pages, редактор открывается на http://localhost:8090.
Если порт занят, укажите другой: `run.bat 9000`, `./run.sh 9000`, в Docker — `-p 9000:80`.
Для подложки карты нужен интернет; сам редактор работает и без него (Leaflet лежит в `vendor/`).

## Как работать

1. **Открыть** `.osm` кнопкой, перетаскиванием файла на карту или кнопкой «Пример» (`example.osm`).
2. **Править** (режимы переключаются кнопками или клавишами):
   - **Выбор (V).** Клик по дороге — справа её атрибуты: тип, название, направление, полосы
     (всего / туда / обратно), скорость, мост, тоннель, кольцо, уровень и все теги списком.
     На карте появляются узлы дороги:
     - перетащить узел — сдвинуть;
     - бросить узел на узел другой дороги — соединить их в перекрёсток (Alt — без прилипания);
     - потянуть полупрозрачную точку посередине отрезка — добавить изгиб;
     - клик по узлу — светофор, разрезать дорогу в этом месте, удалить узел.
   - **Дорога (N).** Клики по карте ставят точки, Enter или двойной клик — готово. Точка на
     существующей дороге или узле сразу становится перекрёстком (оранжевая метка). Атрибуты
     берутся из выбранного **шаблона**: «Магистраль 2+2», «Улица 1+1», «Односторонняя», «Съезд»…
     Шаблон можно применить и к уже существующей дороге.
   - **Светофор (T).** Клик по узлу дороги ставит или убирает светофор; клик по середине отрезка
     добавляет узел со светофором. На пешеходном переходе ставится светофорный переход.
   - **Знак (S).** Выберите знак сверху и кликните по дороге: 2.4 «Уступите дорогу», 2.5 STOP,
     2.1 «Главная дорога», 3.1 «Въезд запрещён», 3.24 «Ограничение скорости» (сразу выставляет
     скорость дороги), 5.21 «Жилая зона». Повторный клик по такому же знаку убирает его.
   - **Переход (P).** Наземный (зебра или со светофором) — клик по дороге. Надземный и подземный —
     рисуются линией поперёк дороги и не соединяются с проезжей частью (мост `layer=1` / тоннель `layer=-1`).
   - **Полосы по направлениям.** У выбранной двусторонней дороги кнопки ± «Туда» и «Обратно» и схема
     полос; записывается `lanes`, `lanes:forward`, `lanes:backward` — так их читает SUMO.
   - **Пешеходы.** У дороги: «по проезжей части нельзя» (`foot=no`), тротуары (`sidewalk`).
     В обзоре — массово: запретить пешеходов на магистралях, разрешить во дворах (по одному шагу отмены).
     Шаблон «Двор — жилая зона» (`living_street`, 20 км/ч, пешеходам можно).
   - **Парковки.** Площадка — шаблон «Парковка (площадка)», обвести и замкнуть кликом по первой точке,
     указать число мест и тип. Вдоль дороги — поле «Парковка вдоль» у дороги.
3. **Проверить.** Вкладка «Проблемы» обновляется после каждой правки, проблемы отмечены на карте
   красными кругами. Для части проблем есть кнопка «Исправить».
4. **Сохранить** (Ctrl+S) под именем команды: `team1` → `team1.osm`. Перед сохранением граф
   проверяется; если есть ошибки, редактор предупредит.

### Анализ и сервисы

- **3D — проверка уровней (клавиша 3, кнопка «В 3D» у дороги, узла или проблемы).** Строится место
  радиусом 150–400 м вокруг выбранного: проезжая часть шириной по полосам с разметкой (кромки, двойная
  осевая, прерывистые между полосами, стрелки у односторонних), мосты с плитой, ограждением и опорами,
  выемки тоннелей, пешеходные мосты и подземные переходы, трамвай, светофоры. Высоты — как считает
  контейнер Webots на сервере: уровень `layer` = 5 м, пандусы 100 м. Земля полупрозрачная, тоннели видны
  сквозь неё. Проблемы графа — красные штыри через все затронутые уровни с подписью («склейка уровней»).
  Клик по дороге в 3D выбирает её для правки, после любой правки 3D перестраивается само, камера остаётся
  на месте. Esc или «✕ К карте» — назад в 2D.
- **Пешеходы (вкладка).** Расчёт пешеходного потока по графу: маршруты от зданий к остановкам и между домами
  по тротуарам и переходам, загрузка тротуаров, анимация. Главное — места, где маршруты пересекают магистраль
  **без перехода**, с кнопкой «Поставить зебру». Это анализ графа: сервер проверки (SUMO) пешеходов не моделирует.
- **Правки (вкладка).** «Было — стало» относительно открытого файла: список и подсветка новых, изменённых и
  удалённых объектов, отчёт `.md` для защиты (таблица «было/стало» по показателям и ошибкам), **обмен правками**:
  экспорт своих правок в `.json` и вливание правок товарища, сделанных на том же исходном файле (конфликты
  пропускаются и показываются).
- **Отправка на сервер проверки** прямо из редактора: токен команды → место в очереди → три видео. Из Docker-образа
  работает сразу (nginx проксирует `/checker/` на `CHECKER_URL`); при запуске другим способом сервер должен
  разрешать запросы из браузера (CORS) — иначе загрузите сохранённый файл через сайт сервера.
- **Автозаполнение пропусков** (обзор): полосы и скорость по классу дороги только там, где не указано;
  значения по умолчанию редактируются, перед применением подсвечивается, что изменится.
  Если значения совпадают с умолчаниями SUMO, симуляция от этого не меняется — реальный эффект дают
  реальные значения, которые вносят транспортники.
- **Линейка (M)**, **ширина дороги**, **автосохранение** в браузере (после закрытой вкладки редактор
  предложит восстановить работу).

**Раскраска** (сверху): по классу дороги, по числу полос, по скорости, по доступу пешеходов.
В тематических раскрасках дороги без данных выделены (красный пунктир — нет числа полос), так видно,
что осталось заполнить. Толщина линии всегда соответствует числу полос.

Все правки отменяются и повторяются (Ctrl+Z / Ctrl+Y), до 300 шагов.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| V / N / T / S / P / M | режим выбора / новой дороги / светофора / знака / перехода / линейка |
| 3 | 3D-просмотр видимой области |
| R | развернуть выбранную дорогу (меняются и теги `:forward`/`:backward`) |
| X | разрезать дорогу в выбранном узле |
| Delete | удалить выбранное |
| Enter, Backspace, Esc | при рисовании: готово / убрать точку / отмена |
| Ctrl+Z, Ctrl+Y, Ctrl+S, Ctrl+O | отменить, повторить, сохранить, открыть |
| F / B | скрыть или показать тротуары / здания |

Клавиши работают и в русской раскладке.

## Проверка графа

Проверяются только дороги для машин — по ним MatSim строит маршруты, а SUMO пускает машины.

| Проблема | Что это | Чем грозит на сервере | Исправление |
|---|---|---|---|
| Изолированный кусок | часть сети не связана с основной | машины туда не попадают — участок выпадает из модели | вручную: соединить; изолированный двор — «Это нормально» |
| Односторонний тупик | на односторонней улице можно въехать, но нельзя выехать (или наоборот) | участок выпадает из маршрутов | вручную: направление или связь; во дворе — «Это нормально» |
| Разорванный перекрёсток | конец дороги в паре метров от другой дороги, но не соединён | обрыв маршрута, телепортации | автоматически: слить узлы или притянуть конец на дорогу |
| Пересечение без перекрёстка | дороги пересекаются без общего узла, не мост и не тоннель | в 3D машины проезжают «сквозь» дорогу | автоматически: общий узел в точке пересечения |
| Мост без уровня | `bridge=yes` без `layer` | в Webots мост на одной высоте с дорогой под ним | автоматически: `layer=1` |
| Ловушка | участок, куда можно въехать, но нельзя выехать (с учётом направлений; сильная связность графа) | машины в нём не ездят: `randomTrips` на сервере отбрасывает такие поездки и подбирает другие, прогон не падает, но модель беднее | вручную; во дворе — «Это нормально» |
| Светофор на подходе | светофор стоит на точке перед перекрёстком, а не на самом перекрёстке | SUMO делает отдельный светофор посреди дороги, перекрёсток остаётся нерегулируемым | автоматически: перенести на перекрёсток |
| Программа светофора | подъезд ни в одной фазе не получает зелёный | машины на этом подъезде стоят до телепортации | вручную: добавить подъезд в фазу |
| Склеенный перекрёсток | мост или тоннель имеет общий узел с дорогой другого уровня посередине пролёта | в Webots машины «спрыгивают» с моста на дорогу под ним | автоматически: расклеить узел |
| Неверное направление | части одной улицы односторонние навстречу друг другу | поток упирается | вручную |

Концы дорог у края выгрузки тупиками не считаются — там дорога просто уходит за границу фрагмента.

**Красное — ошибка карты, жёлтое — «проверьте».** Тупики, односторонние въезды и изолированные проезды
**во дворах** (`service`, `living_street`) бывают нормой: въезд с одной улицы, выезд на другую. Такие места
отмечаются кнопкой **«Это нормально»** — на узел ставится стандартный тег OSM `noexit=yes`, и проверка
больше его не показывает.

Проверено на копии конвейера сервера: тупики, «ловушки» и изолированные дворы прогон не роняют —
`randomTrips` проверяет достижимость и заменяет недостижимые поездки (во всех опытах 100 из 100).

## Полосы, стрелки, траектории, расчёт

- **Полосы на крупном масштабе.** От масштаба 17 линия дороги распадается на полосы и рисуется в метрах, как на спутнике: проезжая часть
  шириной `width` или «полосы × 3,2 м», кромки, двойная осевая, прерывистые между полосами и **стрелки на
  каждой полосе** у перекрёстка. Где у продолжения той же дороги другое число полос, проезжая часть
  **плавно сужается или расширяется на 25 м** (лишняя полоса сходит на нет), а где улица расходится на две
  проезжие части, каждая выходит из своей половины. То же в 3D. Красный «?» — число полос не указано, нарисовано по умолчанию для класса.
- **Стрелки по полосам** — в свойствах дороги под «Полосы»: для каждой полосы «прямо», «налево»,
  «направо», их сочетания, разворот. Пишутся стандартные теги OSM `turn:lanes`, `turn:lanes:forward`,
  `turn:lanes:backward` (полосы слева направо по ходу движения).
- **Траектории манёвров (J).** На перекрёстках рисуются все разрешённые манёвры: оранжевые — налево,
  синие — направо, серые — прямо, фиолетовые — разворот (только по стрелке). Точки пересечения траекторий
  с разных подъездов — **конфликтные точки**: красные — с левым поворотом (самые опасные), жёлтые — прочие.
  В свойствах узла — сводка: сколько манёвров, сколько запрещено стрелками, сколько конфликтов.
- **Расчёт регулируемого перекрёстка** — в разделе светофора: интенсивность каждого подъезда (авт/ч) →
  пропускная способность, загрузка, задержка по Вебстеру, очередь к началу зелёного (машин и метров),
  уровень обслуживания A–F (как в HCM), оптимальный цикл Вебстера и кнопка «Подобрать фазы по Вебстеру».
- **Знаки приоритета по данным** (обзор): на нерегулируемых перекрёстках разных по классу дорог —
  «Уступите дорогу» второстепенным подъездам (выезды из дворов пропускаются), по желанию «Главная дорога».
  Сначала показываются на карте, потом пишутся в файл.
- **Объяснение проблемы.** Клик по кружку проблемы на карте или «Показать» в списке — окно: что это,
  чем грозит, что делать, затронутые дороги и кнопки исправления; затронутые дороги подсвечены.

- **Предполагаемые стрелки.** Если стрелки у полосы не заданы, на карте показаны предполагаемые
  (жёлтым пунктиром): крайняя левая — налево, крайняя правая — прямо и направо, с учётом запретов
  манёвров. Кнопка «Стрелки по умолчанию» у дороги или «Заполнить по нормам» в обзоре записывают их в файл.
- **Знаки из файла.** Запреты манёвров (отношения `type=restriction`: «поворот налево запрещён», «только прямо»,
  «разворот запрещён» и т. п.) показываются знаками ПДД на подъезде и учитываются в траекториях. SUMO их тоже
  читает. Отдельных знаков-точек `traffic_sign` в `example.osm` нет; если они есть в файле — показываются.
- **Симуляция перекрёстка без визуализации** — в разделе светофора, кнопка «Симуляция: 1 час»: машины
  приходят случайно с заданной интенсивностью, разъезжаются по секундам на зелёном; итог по подъездам —
  пришло, проехало, осталось в очереди, средняя задержка, доля остановившихся, средняя и наибольшая очередь
  (машин и метров), доля «несработавших» циклов; среднее по 5 прогонам.
- **Не хватает данных.** После открытия файла — уведомление; в обзоре — сколько дорог без числа полос,
  скорости, ширины, покрытия, названия, кнопка «Показать» подсвечивает их, **«Заполнить по нормам»** —
  только пустые поля: ширина = полосы × ширина полосы по СП 42.13330 (магистральные 3,5 м, местные 3,0 м),
  скорость по ПДД (город 60, жилая зона 20), покрытие, стрелки.

## Общественный транспорт (вкладка «ОТ»)

- **Маршруты из файла** — отношения OSM `route=bus/trolleybus/tram` (в `example.osm` их 67): список с
  номерами, показ на карте по одному или все сразу. Маршруты читаются из `.osm`, без внешних API: у 2ГИС
  открытого API маршрутов нет, а подключение без ключа ненадёжно.
- **Остановки из файла** и **новые остановки** — режим «Остановка» (O): клик по карте ставит остановку
  (`highway=bus_stop` + `public_transport=platform`), зона доступности пересчитывается сразу.
- **Пешеходная доступность остановок** — зона, из которой до ближайшей остановки можно дойти за 3–10 минут
  по тротуарам и переходам (4,5 км/ч), и доля зданий в ней. С галочкой «Учитывать рельеф» скорость
  меняется по уклону (функция Тоблера).
- **Рельеф** — горизонтали по открытой цифровой модели рельефа Terrarium (AWS), нужен интернет.

## Горячие клавиши настраиваются

Вкладка «?» → «Горячие клавиши — можно переназначить»: клик по клавише действия, затем новая клавиша.
Клавиши работают в любой раскладке (по физической кнопке) и сохраняются в браузере.

**Что из этого видит сервер проверки.** Спрос на сервере фиксирован организаторами: SUMO всегда пускает
одни и те же 100 машин (`randomTrips`, зерно 42), MatSim — свои 100 поездок; из `.osm` поток не берётся.
Поэтому интенсивности и расчёт — инструмент инженера внутри редактора, на видео жюри они не попадают.
Стрелки `turn:lanes` сервер тоже не читает (SUMO там запущен без `--osm.turn-lanes`); число полос по
направлениям — читает. Для микромодели с реальными показателями — `tools/sumo_check.py` (ниже).

## Светофорный объект (фазы)

Клик по узлу перекрёстка (или по светофору) → раздел **«Светофор и фазы»**:

- **«Сделать регулируемым» / «Настроить фазы»** — программа на две фазы: встречные подъезды вместе;
- **фазы**: название, подъезды с зелёным (кнопки-чипы), длительности зелёного, жёлтого и «все красные»,
  порядок фаз, добавление и удаление; шаблоны «2 фазы» и «по подъездам»;
- **схема перекрёстка**: стрелки подъездов, зелёные — в выбранной фазе;
- **диаграмма цикла** — как фазовая диаграмма в AnyLogic: строка на подъезд, зелёный/жёлтый/красный по времени;
- **сдвиг цикла** — для «зелёной волны» с соседними светофорами;
- проверка: подъезд, который ни в одной фазе не получает зелёный, — ошибка.

Программа хранится в самом `.osm` на узле перекрёстка, тег `uds:tls` (JSON: подъезды по направлениям и фазы).
SUMO сам такие теги не читает — их переводит `tools/osm_tls_to_sumo.py` в программу светофора SUMO
(`tlLogic`) по готовой сети: каждая связь перекрёстка относится к подъезду по направлению въезда.

- **Локально:** `python tools/sumo_check.py team1.osm` — применяет программы и показывает их в отчёте.
- **На сервере:** нужна правка контейнера SUMO `sumo-tls-programs.patch` (3 файла, +201 строка): после
  `fix_access.py` вызывается конвертер, затем `netconvert --tllogic-files`. Без программ в файле поведение
  сервера не меняется. **Пока правка не установлена, сервер строит светофорам свои программы.**

## Проверка «как на сервере» без очереди

```bash
pip install eclipse-sumo
python tools/sumo_check.py team1.osm
```

Повторяет шаги контейнера SUMO (тот же `netconvert`, те же типы дорог, запреты `motor_vehicle=no`,
`randomTrips` со 100 машинами и тем же зерном, час модельного времени) без видео — около 15 секунд.
Печатает: сколько маршрутов построено, сколько машин доехало, телепортации, среднее время в пути,
потери времени, время стоянки, число остановок на машину, среднюю скорость и пять самых длинных очередей
(по улицам). Удобно сравнивать варианты карты до отправки на сервер.

## Что из этого видит SUMO

Проверено на `netconvert` 1.28:

| Тег | Эффект в SUMO |
|---|---|
| `lanes:forward=2`, `lanes:backward=1` | 2 полосы туда, 1 обратно |
| `maxspeed` (в т. ч. от знака 3.24) | скорость на рёбрах |
| `foot=no` | пешеходы запрещены на полосах проезжей части |
| `sidewalk=both/left/right` | отдельные полосы-тротуары (при `--osm.sidewalks`) |
| `highway=traffic_signals` | светофор на перекрёстке |
| `highway=stop` / `give_way` | при импорте **не учитываются** — тип перекрёстка не меняется |
| `uds:tls` (фазы из редактора) | применяются через `tools/osm_tls_to_sumo.py`; на сервере — после правки `sumo-tls-programs.patch` |
